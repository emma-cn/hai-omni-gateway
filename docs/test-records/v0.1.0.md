## 4. 真机事故（本次测试期间发生，非测试触发）

2026-11-19 17:18–17:19，dev 上两个模型换台时打出 OOM，**后端容器 `后端 B 容器` 直接退出**：

```
17:18:52 switch /models/IndexTTS-2.5 from=/models/VoxCPM2
17:18:58 sleep IndexTTS -> RemoteProtocolError: Server disconnected without sending a response.
         card card4: fail /models/IndexTTS-2.5 sleep: ...
17:18:58 switch /models/VoxCPM2 from=/models/IndexTTS-2.5
17:19:03 wakeup VoxCPM2 -> 500 CUDA Error: out of memory
```
`后端 B 容器`：`Exception: Call to wake_up method failed: CUDA Error: out of memory` → `Shutting down` → `Exited (0)`。

这条链路同时命中了 #1（sleep 失败仍继续唤醒）与 #2（状态与显存失配无自愈）：
事故后 `/admin/state` 报 `awake: null`，而 `nvidia-smi` 仍被 后端 A 占着 14 GB —— 下一次任何请求都会再 OOM。
因此 L2 E2E **没有执行**，先留给人工/后续版本恢复后再跑（恢复：`docker restart hai-omni-gateway` 做对账 → `docker start 后端 B 容器`）。

## 6. `5ef7280` 复核（首轮提缺陷后开发已改）

开发在 `5ef7280` 收紧了一处语义，其余未动。逐条复核：

| 缺陷 | `5ef7280` 复核 | 依据 |
|---|---|---|
| #1 睡眠失败仍继续唤醒 | **仍在** | `scheduler.py` 的 `else: self._event("fail", cur, f"sleep: {err}")` 之后仍无条件 `client.wake(target)` |
| #2 状态与显存失配无自愈 | **仍在** | 无任何人提供的对账入口；`force_sleep` 仍以 `_awake != model` 早退 |
| #3 无熔断 | **仍在** | 无 down 标记/退避，只有单次 503 |
| #4 长任务租约 | **仍在** | `grep -rn lease_s src/` 仍只有配置与展示 |
| #5 多视频模型轮询 400 | **仍在** | `grep -rn "job_id\|video_jobs" src/` 命中 0，仍无 job→model 记账 |
| #6 queue_limit 未生效 | **仍在** | `grep -rn queue_limit src/` 仍只有 config 两行 |
| #7 缺 X-Omni-Wake-ETA | **仍在** | `grep -rn X-Omni-Wake-ETA src/` 命中 0 |
| #8 管理面无鉴权 | **仍在** | `grep -rniE "admin_token\|authorization\|x-api-key" src/` 命中 0 |

**已修 / 语义收紧（原用例要跟着改）**：drain 超时。原实现"超时后照样换台"，`5ef7280` 改为
`raise DrainTimeout` → API 层 `503 + Retry-After: 5`（`error.type = drain_timeout`），
依据是上游"暂停未完成 = 暂停失败，不许 sleep"。
`tests/test_scheduler.py::test_drain_timeout_switches_anyway` 因此改写为
`test_drain_timeout_refuses_switch`（断言拒绝换台、旧模型仍醒、没 sleep、没唤醒目标），
并新增 `tests/test_acceptance.py::test_acceptance_drain_timeout_returns_503_with_retry_after`。

> 这是本版本唯一一处「用例必须跟着契约改」的地方：**契约变了要改用例，不是让用例迁就旧行为**。
